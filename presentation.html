Architecture

One exposed port

The gateway is the only externally reachable port. Everything else is cluster-internal, reachable only by ClusterIP.

03

The core

Capacity is battery

Capacity is battery range, which moves with distance flown and payload weight. The constraint depends on the route you are still choosing. Python lives here and nowhere else.

04

Architecture

Event-driven, not polled

Five services, one event. One bound queue per consumer, so each gets a full copy. The payload is the locked TelemetryEvent contract: drone_id, position, battery_pct, event_type.

05

Platform

Thirteen repos

  • Nine ship images. The rest are docs and infra.
  • Each with its own remote, CI and protected main.
  • swarmops-contracts holds the shared types.

Polyrepo costs coordination on every shared change. The contracts repo is what buys it back. Without it, services drift on field names.

06

Packaging

One chart, not nine

  • One template stamps out all 8 services, instead of 8 near-duplicate YAML files.
  • Mongo and RabbitMQ aren't hand-written — they're pulled in as Bitnami dependencies.
  • drone-simulator is the one exception: it's a background worker, so it skips the Service object entirely.

Why services: is a map, not a list: CI bumps one service's image tag by layering a tiny override file on top. Helm merges maps key-by-key, so that touches only that one service — but it replaces lists outright, which would've wiped out the other 7.

07

Provisioning

Split by blast radius

Not stylistic. A cost-saving teardown once took all nine ECR repos down with the cluster. Terraform Cloud, VCS-driven, no local applies.

08

End to end

From commit to cluster

Local dev is a separate stack. swarmops-local's docker compose brings the whole system up on a laptop with its own database. Nothing syncs between the two.

09

Continuous integration

PRs never touch the cluster

A PR is unprivileged, not unverified. It still lints, tests and builds. Merging is what crosses the boundary. Zero static keys, and the tag latest is never used.

10

Continuous delivery

A deploy is a git commit

CI edits one YAML node with yq: a path, not a text replace, so it can't hit another service's block or fail silently. Nobody runs helm upgrade.

11

Progressive delivery

Canary on the optimizer

Error rate5xx ≤ 5%
Latency p95≤ 2s
Latency p99≤ 3s
TolerancefailureLimit 2

Every query is scoped to the canary's own pods by pod-template-hash. Without it, a broken canary's errors are diluted by the 80% of traffic still hitting healthy stable pods, and the gate only catches what already broke the whole service. Limitation: no trafficRouting plugin, so weight is approximated by replica count.

12

Observability

Installed by Argo CD

  • /metrics on all seven app services.
  • Prometheus and Loki are Applications too.
  • Three real algorithm metrics on the dashboard.

planning_assignment_quality_vs_greedy compares the real matcher's route distance against the greedy baseline on the same input. Verified live, non-zero.

14

Two more stories worth telling

The two that mattered

RabbitMQ self-healed live, by accident Minutes after fixing fleet/notification/telemetry-service's reconnect-on-drop handling, RabbitMQ's pod got rescheduled again (an Argo CD hard-refresh side effect). All three pods hit the exact failure the fix targeted, in real time — dropped, reconnected, /health correctly went 503, kubelet restarted them, clean reconnect once RabbitMQ was back. Zero manual intervention.
Your camera-feed race, for the record Frame/tag interleaving where only one of two concurrent drone feeds ever rendered, plus a relay bug where producers received every other producer's traffic unread forever until it stalled. Real concurrency bugs, good to walk through live.

One's proof the resilience fix holds up under a real failure; the other's a real bug, worth walking through live.
